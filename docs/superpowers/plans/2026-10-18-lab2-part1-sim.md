# Lab 2 Part 1 Simulation Implementation Plan

> **For agentic workers:** executed by parallel subagents, one per task in Wave 1, each
> owning a disjoint set of files. Read the spec first.

**Goal:** `just lab2 sim submission:=DIR [--final]` runs the Lab 2 stack on the RC
simulator's car on one straight, live (RViz + dashboard), grades the live run, cleans up.

**Spec:** `docs/design/lab2-part1-sim-design.md` (binding). Course phase plan:
`~/repos/ntu-sdv-course/2026/labs/Lab2/lab2-part1-sim.md`.

## Global constraints

- ROS 2 Humble, Autoware 1.5.0 at `/opt/autoware/1.5.0`, Python only for new nodes.
- Setup is `./setup.sh` + `just build`; any new apt dependency goes into the setup
  registry (`setup/autosdv_setup/registry.py`) or an existing step, never a manual step.
- Launch testing with `play_launch`, started under `setsid`, killed by process group.
  Never kill process groups you did not start (other users' stacks run on this host).
- Temp files under `./tmp/` only. Never search `/` or `$HOME` broadly.
- Each agent uses its own `ROS_DOMAIN_ID` (given in its dispatch) and its own
  `--web-addr` port; builds with `flock tmp/build.lock colcon build --base-paths src
  --symlink-install --cmake-args -DCMAKE_BUILD_TYPE=Release --packages-select <pkg>`.
- Submodule `src/vehicle/autosdv_vehicle_launch` (branch `1.5.0`): edit on that branch,
  do not commit (the controller commits after review: submodule first, then pin).
- Agents do not commit and do not push. They leave a report file.
- The real car's behaviour must not change: everything new in the vehicle interface is
  `hardware:=sim` only.
- No reference controller in any file a student receives (course handout, stub).
- Match surrounding code style (flake8 settings of each package; 99-char lines in
  rc_sim, the package's own in others).

**Runner contract (P3 ↔ P4):** the grader node takes params `profile_file`, `out_dir`,
`variant`; on finish it writes `out_dir/trace.csv` and `out_dir/marks.json` (keys:
`variant`, `valid`, `invalid_reason`, `passed`, `total`, `checks`), publishes the final
status and stays alive. The runner waits for `marks.json` (timeout ~180 s sim), then
stops the stack by process group. `--final` repeats for `nominal`, `low_batt`, `low_mu`
and writes `final.json` with `marks = 25 * sum(passed) / sum(total)` (45 if all valid;
an invalid run counts 0 of 15).

**Launch args of `lab2_part1_sim.launch.xml`** (P3): `variant`, `course_dir`,
`speed_controller_class`, `speed_controller_params`, `out_dir`, `rviz`, `gui`,
`real_time_factor`, `lockstep` (default true).

## Wave 1 (parallel)

### P1: Clock handshake (lockstep)
Plant waits, deadline by deadline, for acks from `velocity_report` and the actuator (sim
only) before advancing `/clock`; equal instants: velocity_report first; timeout → invalid
(status topic), no hang. Edges stay published before the clock tick that covers them.
`just sim rc` and its tests keep passing (`python3 -m pytest src/sim/autosdv_rc_sim/test`,
vehicle interface tests; `smoke.py` once). Write `part1_tolerance.py`: runs a given
submission N times quiet and N times under busy loops (own PGID) via P3's runner
(`scripts/testing/lab2/part1_run.py --out ...`), compares `marks.json` per check, prints
the spread and the verdict agreement table. Until P3 lands, prove the handshake with the
rc_sim stack: a stress run of `just sim rc` shows the actuator never computing on a
report older than its period (log or test). Unit-test the deadline scheduler without ROS.

### P2: The student controller
Skeleton/stub with TODOs (spec table), TA reference, defaults YAML with FF constants
measured on the nominal rc_sim model (derive them with the headless plant: steady speed
vs PWM, fit `PWM = init + d + v/g`, document how). Offline tests (no ROS): the reference's
P/I/D/anti-windup/brake behaviour, clamp, reset, contract (imports allowed list as in
the Lab 2 handout), and that the stub holds neutral. `submission.py --part1 DIR`
(`<id>_lab_2_1/` holding `lab2_speed/`, or the package itself): `--pythonpath`,
`--launch-args` printing `speed_controller_class:=lab2_speed.speed_pid:SpeedPID` and
`speed_controller_params:={...}` from `config/speed_pid.yaml` (validated: only the
spec's keys, ranges, bools). Course handout `lab2_speed/` mirrors the stub, the yaml,
a README (the interface, the parameters, how to run `just lab2 sim`), and a `selfcheck.py`
(contract + unit checks of the TODOs, no grading). If headless speed matters for tests,
the rc_sim `Lockstep` harness may be given an optional speed-controller-class hook
(coordinate: that file is rc_sim's `lockstep.py`; P1 does not touch it).

### P3: Stack, course, scenario, runner
Course generator (`part1/course.py`) writing `path.csv` (x, y, v), `course.yaml`,
`lanelet2_map.osm`, `map_projector_info.yaml`, `part1_profile.yaml` — reuse rc_sim's
`track.py` profile math and lanelet writer where possible, and the waypoint lab's
course format (`course.py`, `uturn.py`). Part 1 configs: path publisher (`v_max` 11.5,
`decel` 2.5, window ahead long enough for 11 m/s), a diagnostic graph without the marker
checks (3.0 s timeouts on the 1 Hz /adapi diags, as rc_sim), gate limits that let 11 m/s
and 2.5 m/s^2 through. Launch composing the waypoint nodes (`waypoint_nodes.launch.xml`
or pieces of `waypoint_follow_bench.launch.xml`), Autoware control's gate and the AD API
engage path, the vehicle interface with `hardware:=sim`, the rc_sim plant (owns /clock,
`variant`), true pose (no EKF/markers), the grader, the dashboard and RViz (P4's nodes;
until they exist, launch tolerates their absence via `gui:=false`). Scenario node:
initial pose/route as the lab does (start box), wait for autonomous available, engage,
publish events, raise the emergency at `estop_trigger_s`, clear after 1 s at rest, abort
with a reason on timeout. Runner `part1_run.py` + `just lab2 sim` (`submission:=DIR`,
`variant:=`, `--final`, `rviz:=false gui:=false`), setsid + PGID cleanup, prints marks,
non-zero exit when invalid. Verify with the TA reference (P2) or `AckermannSpeedPID`
with the rc_sim reference coefficients while P2 is in flight.

### P4: Grader, dashboard, RViz
`part1/metrics.py`: pure functions from a trace (columns as the spec's outputs) and the
profile → the 15 checks + validity; reuse rc_sim `grade.py` metric code (import it or
move shared helpers into a module both use; do not change rc_sim's graded numbers —
its golden tests must stay green). Limits table in `metrics.py`, placeholders until
`part1_calibrate.py` (runs the reference via P3's runner on the three variants, prints
1.5× worst case per calibrated metric) is run in Wave 2. Grader node: subscribes, builds
the 100 Hz trace on sim time, evaluates live (partial checks as segments complete),
publishes status/violations, writes outputs, detects finish (at rest past the stop line
for 2 s, or the scenario's abort) and invalidity (MRM, controller fault mode, lockstep
status not ok, timeout). Dashboard: matplotlib in Qt (`matplotlib.backends.backend_qtagg`
or qt5agg), rolling plots of speed (target/measured/true), PWM (neutral line, brake zone
shaded), distance to stop line, violation spans, final marks table; runs on sim time
from the status/trace topics; closes cleanly on SIGINT/SIGTERM. RViz config: Autoware
map/vehicle displays, path, violation markers, a follow view. Unit tests for every
metric on synthetic traces (pass and fail cases).
